我怎样制作软件使用教程：键鼠显示、鼠标缩放和自动截图

发表于2025-11-02|更新于2025-11-02|学习
|总字数:1.7k|阅读时长:5分钟|浏览量:

之前为了教新生使用我写的自动化程序，我需要录一套软件教程。真正开始做以后才发现，普通录屏只能把画面录下来，却不一定能把操作讲清楚：鼠标指针太小，快捷键没有提示，界面上的文字一缩就看不见。要是改做图文教程，几十张截图又得一张张截、一张张标。

我在论坛和 GitHub 上找了一圈，最后把需求拆成了三件事：显示键鼠操作、让录制画面跟随鼠标缩放，以及自动记录每一步操作。下面是我试过的工具和目前仍在使用的组合。

把键鼠操作显示出来

直接用 keyviz

如果不想折腾 OBS，我最推荐 keyviz。安装后就能把按键和鼠标点击显示在屏幕上，位置、颜色、大小和动画都可以调整。

它的优点是简单，开着就能用，平时做演示也方便。它采用屏幕顶层渲染，因此提示会同时出现在我自己的屏幕上。部分全屏程序可能把覆盖层挡住，遇到这种情况就需要换成 OBS 内部叠加。

同类工具还有 Carnac、KeyCastOW、Screenkey 和 KeyPress OSD。Carnac 与 KeyCastOW 更适合 Windows，Screenkey 主要面向 Linux。它们解决的是同一个问题，选一个在自己的系统上稳定运行的就够了。

在 OBS 里用 input-overlay

有时我不希望键鼠提示挡住自己操作，只想让观众在录像里看到。这时我会用 OBS input-overlay。提示作为 OBS 来源叠加在成片中，不会覆盖实际桌面，录制全屏程序时也更稳定。

插件有很大的自定义空间。除了键盘、鼠标布局，还可以使用项目里的 input-history-windows 预设显示按键历史。安装后要到 OBS 的“工具 -> 输入叠加设置 -> 远程连接”，勾选“通过 websocket 服务器转发事件”，否则输入历史可能没有反应。

如果还需要换一套更醒目的鼠标样式，可以试试 cursor-skin-fx。我不会为了好看加太多光效，但在深色软件界面里，给指针增加一点轮廓确实更容易看清。

让录制画面跟着鼠标缩放

键鼠提示解决了“做了什么”，界面细节仍然可能太小。这里有两种思路：录完再决定哪里放大，或者在录制时直接控制镜头。

Cap：先录制，后处理

Cap 是一款开源录屏工具。它会先保留完整录制，再让我在编辑阶段选择哪些片段跟随鼠标、何时缩放。

这种方式容错率高。录制时不必惦记缩放快捷键，讲错了也能在后期调整。代价是多一道编辑与导出流程，我当时使用时也觉得导出偏慢，画质和速度需要自己取舍。

obs-zoom-to-mouse：边录边缩放

我更常用的是 obs-zoom-to-mouse。它在 OBS 录制过程中根据鼠标位置移动放大区域，通过快捷键控制放大和恢复，录完基本就是成片。

上游版本当时没有适配我使用的新版 OBS，所以我整理了中文版本 obs-zoom-to-mouse-zh，补了高版本兼容和中文说明。这个项目的实现与维护过程，我也单独写过一篇复盘记录。

实时缩放效率很高，也有一个很直接的问题：录制时缩错了，后期没有原始全画面可以重新取景。我一般会用副屏监看 OBS 预览，确认画面确实跟上了鼠标。

类似工具还有 FocuSee、Screen Studio、eSearch 和微软的 ZoomIt。FocuSee 支持 Windows 和 macOS，Screen Studio 主要面向 macOS；eSearch 是跨平台工具；ZoomIt 更像演示时临时放大和标注的工具。它们的工作流不完全一样，不能只看最终动效来选。

自动生成带截图的步骤文档

有些内容做成视频反而不方便查。比如安装、配置和排错步骤，我更愿意整理成带截图的 SOP。

网页操作：Scribe、Tango 和 igenflow

Scribe、Tango 和 igenflow 可以记录浏览器里的点击过程，自动给每一步配截图和初步说明。短流程生成得很快，适合后台操作、网页配置和产品使用说明。

它们依赖浏览器扩展或网页环境，桌面软件通常录不到。自动生成的文字也只能当草稿，我还是会重新删掉多余步骤，统一按钮名称，并补上容易出错的地方。

Windows 桌面软件：PSR 步骤记录器

Windows 自带的 PSR（问题步骤记录器）更适合桌面程序。在运行窗口输入 psr 就能打开。开始记录后，它会根据点击自动截图、高亮操作区域，并把控件名称和操作说明一起写进报告，最后导出为可以用浏览器打开的 .mht 文件。

PSR 很省事，但不能再把它当成长久方案。微软已经将它标记为弃用，并说明会在后续 Windows 版本中移除。现阶段还能用就可以继续用，同时最好保留原始截图，方便以后迁移到其他文档工具。具体用法和替代建议可以查看微软的 PSR 说明。

我最后采用的工作流

现在录视频时，我用 keyviz 增强鼠标提示，在 OBS 中用 input-overlay 显示键盘操作，再用 obs-zoom-to-mouse 控制局部放大。这样录制完成后通常只需要剪掉开头和停顿，不必重新做缩放动画。

需要图文说明时，我先用 PSR 留下完整操作记录，再挑选真正需要的截图。初稿会交给 Gemini 帮忙整理措辞，但软件名称、按钮路径和报错信息必须自己核对。涉及账号、密钥或内部系统的截图，我不会直接上传到在线工具。

这套组合不是固定答案。需要反复修改镜头时，Cap 的后期工作流更稳；只录网页操作时，Scribe 一类工具更省时间；想快速完成一段桌面软件演示，我还是会选 OBS。先看自己最不想花时间的环节，再决定装什么工具，比把所有插件都塞进录制流程实际得多。
